# 博客写作角色系统

博客的笔名署名体系:5 个写作角色,每个角色有独立的人设、文风、选题边界和禁区。
目的:① 避免全站一个腔调的"批量 AI 感";② 用一致的角色声音积累 E-E-A-T;③ 批量产文时有可复用的风格规范。

## 结构

- `src/content/authors.ts` — 作者注册表:笔名 + 各语言 role/bio(署名栏与 JSON-LD 的数据源)。
- `src/content/posts.ts` — 比文章必须填 `author` 字段(TS 类型限定只能选注册过的角色)。
- `docs/personas/<id>.md` — 角色卡:该角色的文风规则、句式、禁区。**写文前先读对应角色卡。**

## 使用规则

1. **选题定角色**:新文章先按选题簇选角色(上表),一篇只属于一个角色;跨界选题选主读者对应的角色,越界部分点到为止或互链给对应角色的文章。
2. **按角色卡写作**:确定角色后,通读该角色的 `.md` 卡片再动笔;文风规则(必须/禁止)是硬约束。
3. **全语言同一角色**:同一篇文章的 8 个语言版本共用同一 author,笔名不翻译(role/bio 有各语言版本)。
4. **两处同步**:调整角色人设时,`authors.ts` 的 role/bio 与 `docs/personas/` 角色卡必须一起改。
5. **产量配比**按季度对照流量数据回顾,不作为硬约束。

## 新增一篇文章的操作流程

1. **定选题与角色**:按选题簇对照上表选定 1 个角色(跨界选题归主读者所在的桌),并在 `docs/us-seo-content-plan.md` 登记该选题;
2. **通读角色卡** `docs/personas/<id>.md`:卡内"必须"是硬约束、"禁止"不可越;开头句式仅作参考,不照抄;
3. **写正文** `src/content/blog/<slug>.en.mdx`(en 先行,恰好一个 H1;多语言跟进规则见规范 §3.2);
4. **接线四步**(`docs/DEVELOPMENT-STANDARDS.md` §3.4):`registry.ts` 注册正文 → `posts.ts` 登记 `slug / author / date / updated / image` + i18n 标题描述 → `related.ts` 登记内链;
5. **验收**:`npm run lint`、`npx tsc --noEmit`、`npm test` 三零;抽查文章页署名栏与 JSON-LD 显示所选角色。

## 质量门控与反同质化(2026-10 起)

发布节奏按**质量门控**,不按日历门控——目标是避免被归入 Google"规模化低价值内容",而不是让内容更难被检测:

- **节奏**:当前阶段每周 3–5 篇;GSC 出现稳定正反馈(单篇 6–8 周内有曝光)后再爬坡到每天 1 篇;
- **发布门槛**:每篇必须携带角色卡「发布门槛」一节列出的体验资产(一手案例 / 实测记录 / 一手文献 / 原创模板),缺则退回重写;
- **反同质化**:同一角色的相邻文章不连排相同 H2 骨架;字数按搜索意图浮动(约 600–2500 词),不为凑量写等长文章;每篇至少 1 个非文本资产(可打印 PDF、对照表、截图);
- **效果检查**:上线 6–8 周无曝光的选题模式停止复用;`/about` 页已公示五个桌位(编辑声开口径),新角色上线需同步该页。

## 选题池(Trends 管道)

`scripts/trends-backlog.mjs`(定时任务每周一运行,geo=US)维护 `docs/trends-backlog.md`,两路数据源:

- **主源:种子词相关查询上升榜**——以 6 个选题簇圆心词(handwriting / cursive / handwriting practice / handwriting worksheets / name tracing / calligraphy)为种子,抓 Google Trends「相关查询 Rising」近 7 天涨幅,去重计数。新词中**涨幅 Breakout 或 ≥100%** 的由定时任务写进「人工评估」,能挂上体验资产才进排期(定角色 → 走「新增一篇文章的操作流程」);
- **参考源:大众每日热搜 RSS**——全类别日榜,仅供观察,与站内主题无交集是常态;
- **news 性质的日级热点默认不接**(博客排名窗口追不上新闻生命周期);季节性选题(圣诞、返校季)提前 6–8 周发布。

注:Trends 相关查询是非官方接口且限流较狠(429 惩罚窗口可达小时级),脚本已带退避重试与 10 秒种子间隔;个别种子失败会告警跳过,不影响其余种子与 general 池。

## 诚信红线(重要)

- 角色 = **编辑部写作声音**,不是可验证的真实个人。**禁止**虚构可验证的资历:执业执照、学位、任职机构、出版物的"作者经历"。
- role/bio 只描述视角与写作范围(如"课堂视角""科学桌"),不声明具体个人身份;后续做作者页时保持同一口径。
- 科学桌引证必须可溯源;工具桌的"实测"必须真的测过。
- 新增角色的门槛:只有出现装不进现有 5 桌的**新内容支柱**时才加,并同步更新本 README 与 `authors.ts`。
