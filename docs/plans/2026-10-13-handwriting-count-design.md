# 手写计数

- 日期:2026-10-13
- 状态:已落地
- 名字:导航 Handwriting Count,页面标题 Count Handwriting From a Photo,中文导航「手写计数」,中文标题「数一数这张手写有多少字」
- 路由:`/handwriting-count`
- 登记:`docs/us-seo-content-plan.md` §二十三。配套文 `count-words-in-handwriting`(en,Theo)已落地

用户上传一张手写照片。模型把照片转成文字。代码按这段文字统计字、单词、字母、数字和标点。用户可以改文字,数字立刻重算,不再请求模型。

照片和转写都不入库。转写只留在这一页的内存里,离开或再传一张就没了。

## 谁在用

想知道一张手写有多少字的人。中文作文数的是字,英文笔记数的是单词,同一张图里可以两种都有。字母、数字、标点分开列出,避免把它们加进一个总字数。

和 `/handwriting-check` 挨在一起:那一页看拉丁字母好不好认,这一页把字读出来并计数。两页不共用每天的 3 次。

## 页面

8 语言界面。收在 `/tools` 练习纸分组,紧挨手写评分,页头下拉不单列。

打开先看到四句说明:

- 一张手写照片,什么语言都可以。
- 先得到文字,再按字、单词、字母、数字分开数。看不清的地方写成 □,不计入数字。文字可以改,数字跟着变。
- 照片送给模型看完即丢,不保存。文字留在这一页,直到离开或再传一张。
- 每天 3 次,第二天重新计算。页面打开就显示今天还剩几次。

上传或拍照后,浏览器把图压成长边 1600、质量 0.85 的 JPEG,再 `POST /api/handwriting-count`。体积上限 2MB。这一页不调用 `fileToPaperImage`,图不进 localStorage。压图函数抄评分页那一份,不改评分组件。等待时收起上传按钮,照片上有转圈,并写明「正在读这张照片」和请留在这一页。页头标题和说明留在原处。

读完之后,数字在上,照片和文字在下。宽屏时照片在左、文字框在右;窄屏先照片后文字。文字框可编辑,保留换行。旁边两个按钮:「复制文字」「再传一张」。复制出去的是框里的原文,含 □ 和换行。再传一张会清掉照片、文字、备注和数字。

数字只显示大于 0 的项:

- 只有字:大号是字数。
- 只有单词:大号是单词数,下面是字母数。全是西里尔、阿拉伯等非拉丁字母时,字母那一行写「其他字母」。
- 字和单词都有:两个大号并排。
- 没有字也没有单词、只有数字:大号是数字个数。
- 标点、看不清的处数、其他符号(如表情)各占一行小字,为 0 不显示。

模型若跳过了划掉的字或印刷体,备注用当前界面语言写一句,放在数字下面。用户改文字时备注留着,再传一张才清掉。转写超过上限被截断时,加一句「读到的文字在这里截断了」。

页底有一句指向 `/handwriting-check`:想看这张字好不好认,去评分页。这一轮不改评分页。

### 何时没有数字

- 照片模糊、切掉字或反光严重:请重拍。照片还留在页面上。
- 没有手写:显示没看到手写。整页印刷体、没有手写,也走这一条。
- 模型两次都没返回能用的 JSON,或请求超时、供应商报错、没配密钥:「这次没读成,可以再试」。不把供应商原文给用户。

看不清但还有能读的字:照常给出数字,并写看不清几处。

## 计数

`countTranscript(text)` 是纯函数。接口和页面共用它。模型如果自己写了数字,解析时丢掉。

先做 NFC。每个 □(U+25A1)计为 1 处看不清,然后从文本里拿掉,再数剩下的字。用户删掉一个 □,处数就少一。

| 项 | 规则 |
| --- | --- |
| 字 | 每个汉字、平假名、片假名(含长音「ー」)、谚文音节各算 1。韩文拆开的字母(jamo)若出现,每个也算 1。提示词要求模型输出整音节,拆开是模型没按要求来时的兜底 |
| 字母 | 拉丁字母,含 é 这类带符号的 |
| 其他字母 | 西里尔、希腊、阿拉伯、希伯来、天城文等,凡是字母又不属于上面的字和拉丁字母 |
| 数字 | 每个数码算 1,含全角 ０–９。`2026` 是 4。汉字数字「三」算字,不改成数码 |
| 标点 | Unicode 标点各算 1,含中文的「。」「,」。不并进字、单词、字母、数字 |
| 单词 | 见下方 |
| 忽略 | 空格、换行、控制符 |
| 其他 | 表情和其余符号。只在大于 0 时用小字显示 |

单词的切法:连续的字母(拉丁或其他字母)算一个词。字母两侧都是字母时,撇号 `'` `'` 和连字符 `-` 留在词里,同时仍算一个标点。其余标点、空格、汉字、假名、谚文、数码都会把词切开。

| 文本 | 结果 |
| --- | --- |
| hello | 1 词,5 个字母 |
| hello world | 2 词 |
| don't | 1 词,4 个字母,1 个标点 |
| well-known | 1 词,9 个字母,1 个标点 |
| hello, world | 2 词。没有空格的 hello,world 也是 2 词 |
| room 12 | 1 词,4 个字母,2 个数字 |
| 3rd | 1 词,2 个字母,1 个数字 |
| 2026 | 0 词,4 个数字 |
| 你好 | 2 字,0 词 |
| こんにちは / コーヒー / 안녕 | 按字面每个字 1,长音算片假名 |
| привет | 1 词,字母进「其他字母」 |
| hello你好 | 1 词,5 个字母,2 字 |
| a □ b | 2 词,2 个字母,看不清 1 处 |

`e.g.` 这种缩写会被句点切成两个词。这一版接受这个切法。

用户把文字改到全空时,各项显示为没有可数的内容,页面仍留在结果态,不改成「没看到手写」。

## 模型

看图请求收成 `askGlmVision(prompt, jpeg)`,放在 `src/lib/glmVision.ts`。评分路由改成调用它,请求的写法保持不变:同一个地址、密钥、模型名、60 秒超时、data URL、只读 `choices[0].message.content`。环境变量仍是 `TEXT_API_KEY`、`TEXT_BASE_URL`、`TEXT_MODEL`,不新增。

提示词由 `buildCountPrompt(locale)` 生成。要求只回 JSON。备注用 `locale` 对应的语言,和评分页同一套八种语言名。要点:

- 只转写手写。能分清时跳过页眉、页码、格线、印刷说明。整页都是印刷体、没有手写,返回 `{"status":"empty"}`。
- 划掉的不写入转写。
- 不改错字,不翻译,不补看不清的笔画。
- 看不清的每一处写一个 □。
- 保留换行。汉字、假名、谚文之间不加空格。拼音文字的词与词之间留空格。
- 纸上写的是数码就写成数码。汉字数字保持汉字。谚文写成整音节。
- 模糊、切掉字或反光严重: `{"status":"retake"}`。
- 否则: `{"status":"counted","transcript":"...","note":"..."}`。只有跳过了划掉的字或印刷体时才写 `note`,一句即可。

JSON 从返回文本里取第一个 `{` 到最后一个 `}`。解析失败再请求一次。第二次仍不行,按「这次没读成」返回。

`parseCountResponse` 放在 `src/lib/handwritingCount.ts`。路由拿到模型文本后只调用它。

校验:

- `retake`:丢掉转写。
- 模型说 `empty`,但转写里有可数内容或 □:按 `counted` 收下。以转写为准。
- 模型说 `counted`,转写是空白且没有 □:改成 `empty`。
- `note` 去掉首尾空白,最长 240 字。只在 `counted` 时保留。
- `transcript` 最长 8000 字。超了就截断,并标 `truncated`。
- 模型附带的任何计数字段忽略。

## 接口

`POST /api/handwriting-count`。查询参数 `locale`,不在八种语言里就用 en。请求体是 JPEG,超过 2MB 拒绝,开头不是 JPEG 魔数也拒绝。响应不带回图片。服务器日志不写图片;Sentry 若打开,请求体不入报。

每天 3 次,记在这台浏览器的 localStorage,键是 `vth-handwriting-count`,和评分的 `vth-handwriting-check` 分开。日切沿用评分页已有的 `calendarDay`、`recordUsage`、`usageLeft`,不另写一套。第二天 0 点次数作废。用完后上传和拍照停用。一次请求计一次:模型读成了、或者返回「这次没读成」,都算。照片不合格、太大、没配密钥、浏览器这边压图失败或网络没发出去,不计。清掉本站数据、换浏览器,次数会重新从 3 开始。接口本身不再按 IP 计数。

| 结果 | 页面 |
| --- | --- |
| `counted` | 数字、备注、照片、可编辑的文字 |
| `empty` | 没看到手写 |
| `retake` | 请重拍 |
| 失败 | 「这次没读成,可以再试」 |

## 文案

用户可见字符串进 `messages/*.json`,8 个语言同一个 PR。命名空间 `handwritingCount`。英文标题是 Count Handwriting From a Photo,描述里带上 handwriting word counter,并写明先转成文字,再按字、单词、字母、数字分开数。导航英文 Handwriting Count,中文「手写计数」。

FAQ 走 `ToolFaq`,三条。这一轮没有配套文章,FAQ 不链博客,避免 404。

1. 照片会留下吗?不会。模型看完即丢。文字留在这一页,直到离开或再传一张。
2. 字、单词、数字分别怎么数?用上面那张表的说法,写成给读者看的句子。标点单独数。
3. 有字看不清怎么办?那个位置是 □,不计入数字。改掉文字后,数字会更新。

## 测试

`npm test` 里的 `handwritingCount.test.ts` 不访问网络。覆盖:

- 本文「计数」表里的每一行。
- 全角数字算数字。句号「。」算标点,不算字。
- 模型在 JSON 里写了计数字段:丢掉,数字只来自转写。
- `retake` 不带转写。空白转写变成 `empty`。`empty` 但转写里有字,按 `counted` 收下。
- 文本里没有 JSON:抛错,交给路由再请求一次。
- `note` 被截到 240 字。转写超过 8000 字被截断并标 `truncated`。
- 提示词要求手写才转写、看不清写 □、不改错字、不翻译,并要求备注用传入的语言。

## 不做

- 在照片上框出每个字
- 拼写检查、翻译、在这一页打分
- 把标点并进字数
- 把照片或转写存到服务器或 localStorage
- 另接一家 OCR
- 分享卡
- 这一轮写配套文章、改评分页
- 按 IP 计数

已知限度:照片长边压到 1600,密密麻麻的一整页会有漏字。用户改文字即可补上。不把多张照片拼成一篇。
