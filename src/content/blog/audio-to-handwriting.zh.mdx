# 录音怎么免费转成手写笔记?浏览器本地方案实测

开会两小时的录音、课堂上老师讲的重点、通勤路上录的灵感——想把它们变成一份能分享的手写笔记,听起来要经过"转写软件 → 复制 → 排版 → 导出"四道工序。

我们现在把它压成了一步:**上传音频文件,直接得到手写排版的文稿**。而且方案是免费、不上传音频的。这篇文章讲清楚原理、实测结果和局限。

## 先说结论:三条路线怎么选

| 路线 | 成本 | 隐私 | 适合 |
| --- | --- | --- | --- |
| 浏览器本地 Whisper(我们采用) | 0 | 音频不出设备 | 日常笔记、隐私敏感内容 |
| 云端 ASR(讯飞/豆包/Groq 等) | 按时长计费或有免费额度 | 音频需上传 | 超长音频、极速需求 |
| 手机听写后复制粘贴 | 0 | 视方案 | 一次性短内容 |

本地路线的唯一代价:首次使用要下载一次模型,转写速度取决于你的设备。

## 我们是怎么实现的(技术原理)

- 音频文件经浏览器 `decodeAudioData` 解码,重采样为 16kHz 单声道;
- Whisper 模型(快速档约 80MB / 高质量档约 250MB,量化为 q8)**自托管在我们自己的域名下**,按 30 秒窗口切分转写;
- 桌面 Chrome 检测到 WebGPU 时走 GPU 加速,否则回退 WASM(CPU);
- 转写结果直接进入编辑器,后续的字体、纸张、导出与手动输入完全一致。

选择自托管而非调用 HuggingFace CDN,是为了绕开跨域限制,也让国内用户可以正常下载模型。

## 实测:一段 TTS 语音的转写结果

测试环境:macOS + Chrome,无独立 GPU(WASM 路径),快速档模型。

- 输入:合成的中文语音"你好,这是一段测试语音,用来验证音频转写功能。"(约 5 秒)
- 输出:"你好,這是一段測試語音,用來驗證音頻轉寫功能。"

内容完全正确,但输出为繁体——这是 base 量级模型的已知倾向,切换「高质量」档或手动改正即可。首次加载模型耗时约 1 分钟(视网速),之后浏览器缓存,不再重复下载。

## 三步用法

1. 在[工具页](/)点击「导入音频文件」,选择 mp3 / wav / m4a 等格式;
2. 等待进度提示(首次含模型下载);
3. 转写文字自动进入编辑器,改错字、选样式、导出。

## 局限,我们直说

- base 模型对强口音、嘈杂环境的准确率有限,重要场合请用高质量档并人工校对;
- 30 分钟以上的音频转写耗时明显,建议分段;
- Safari 对部分音频编码的解码支持不全,推荐桌面 Chrome / Edge。
